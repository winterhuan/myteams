# myteams 方向稿

> 版本：v1.0（意图对齐）  
> 日期：2026-07-05  
> 状态：基于用户描述定稿方向，待细化各团队范例与 Phase 1 范围  

---

## 1. 一句话

**myteams = 养多支专业 Agent 团队的平台——每支队有自己的干活方式，一起把事从想法做到成品；队长期存在，会自己进化。**

不是 Pi 插件，不是单一编排器，不是给所有场景套同一套流水线。

---

## 2. 你要的是什么（用户原话收敛）

```text
· 多个专业团队——短剧、小说、应用开发……各干各的领域
· 每个团队按自己的工作内容，用适合自己的方式
· 共性节奏：先头脑风暴 → 确定方案 → 再实施
· 团队长期存在，可以自主进化
```

这意味着产品中心是 **「多支可养成的专业编队」**，不是 **「一套通用协作原语」**。

---

## 3. 两层结构

```text
myteams（平台）
  └── Team × N（专业团队，长期存在）
        ├── 领域与目标（短剧 / 小说 / 应用开发 …）
        ├── 成员（Agent + 可选的人）
        ├── 工作方式（本团队自己的阶段、角色、产物、规矩）
        ├── 共享现场（队内可见的协作与进展）
        └── 团队记忆（经验、惯例、踩坑——驱动进化）
```

| 层 | 回答的问题 |
|----|------------|
| **平台** | 怎么创建/管理多支队？怎么让人看见各队？Harness 怎么接？ |
| **团队** | 这支队怎么 brainstorm → 定案 → 实施？谁负责什么？产出什么？ |

平台提供 **编队、现场、记忆、接入**；**怎么干活** 交给各 Team 自己的工作方式。

---

## 4. 三支队的例子（说明「各用各的方式」）

共性三段：**头脑风暴 → 确定方案 → 实施**。  
下面展示的是 **同一节奏、不同诠释**——不是平台硬编码的流程。

### 短剧创作队

| 阶段 | 这支队怎么做 | 典型产物 |
|------|--------------|----------|
| 头脑风暴 | 选题、人设、冲突、分集钩子；编剧与策划对等碰撞 | 选题池、人物小传、分集梗概 |
| 确定方案 | 选定本季/本集方向；分场大纲与节奏门禁 | 分集大纲、场景表、制作清单 |
| 实施 | 写剧本 → 分镜/视觉 → 剪辑节奏（按队宪谁审谁做） | 剧本定稿、分镜、可交付成片 |

### 小说创作队

| 阶段 | 这支队怎么做 | 典型产物 |
|------|--------------|----------|
| 头脑风暴 | 世界观、主线、人物弧；发散与收敛交替 | 设定笔记、情节备选、人物关系 |
| 确定方案 | 卷/章结构、POV、伏笔表；统一文风与禁忌 | 章节大纲、写作规范 |
| 实施 | 分章写作 → 互审连贯性 → 修订定稿 | 章节稿、修订记录 |

### 应用开发队

| 阶段 | 这支队怎么做 | 典型产物 |
|------|--------------|----------|
| 头脑风暴 | 需求澄清、方案备选、风险与边界 | 需求摘要、方案对比 |
| 确定方案 | 架构/接口/里程碑；评审门禁 | 设计说明、任务拆分、验收标准 |
| 实施 | 实现 → 交叉 Review → 集成验证 | PR、测试、可运行交付物 |

**要点**：平台不强制「短剧的方案阶段 = 小说的方案阶段」；只保证每支队 **自己定义** 三阶段里发生什么、谁参与、什么算完成。

## 5. 团队如何「长期存在、自主进化」

### 长期存在

- Team 是 **一等对象**：有身份、成员、历史，不是一次性 Session。
- 可以 **连续推进多个作品/项目**（多部短剧、多本小说、多个应用）。
- 人可随时 **旁观、插话、拍板**；默认队自己往前推。

### 自主进化

进化发生在 **团队层**，不是平台替队改代码：

```text
干活 → 收尾沉淀（什么管用 / 什么翻车）
     → 写入团队记忆（原则、模式、教训）
     → 下次 brainstorm / 定案 / 实施 自动带上这些惯例
     → 队宪与工作方式可随实践微调（在自治边界内）
```

借鉴参考项目里的规律，但不照搬形态：

- **OpenCrew**：岗位持久、收尾沉淀、知识层——→ 各 Team 自己的 memory + closeout
- **Clowder**：对等协作、共享记忆、养成——→ 队越干越默契，不是每次从零
- **Multica**：Agent 像同事、有 profile——→ Member 是队里的人格化角色，不是匿名进程

**不搬**：球权状态机、Slack 频道外壳、全局 DAG 编辑器、单一 PM 看板当中心。

## 6. 协作怎么被看见（Hub）

人要能 **看见队内交互**，但不是看终端滚屏：

```text
选一支 Team
  → 当前作品/项目（可选多个，通常聚焦一个）
  → 当前阶段（头脑风暴 / 方案 / 实施）
  → 时间线：谁在说什么、谁接了什么事、关键产物与决策
  → 待你拍板的升级（若有）
```

Hub 是 **各队现场的窗户**；每支队的现场布局可以不同（短剧队突出分集与场景表，开发队突出任务与 diff），由 **Team 工作方式** 驱动展示，不是全平台同一套 UI 模块硬套。

---

## 7. 人的角色

```text
1. 创建或选用一支专业 Team（模板或自建）
2. 下达方向——新作品、新功能、新一季……
3. 旁观协作（可选）
4. 在队升级时做决策（不可逆、方向冲突、验收）
5. 验收成品；队的记忆自动更新
```

人是 **委托人 / 愿景方**，不是队内传话员。各 Team 的 Charter 定义：哪些事队自治，哪些必须叫人。

---

## 8. 与 Harness 的关系

- **执行引擎可插拔**：Pi、Codex、Claude、OpenCode……由 Member 配置，平台不绑 Pi。
- 平台管：**Team、阶段、现场、记忆、成员调度**。
- Harness 管：**单次 Agent 调用与工具执行**。

产品名 **myteams** 强调「我的多支专业队」；Pi 生态可作为 **默认/优先适配的 Harness 之一**，但产品不绑定 Pi，也不是「Pi 的附属 MCP」。

---

## 9. 产品边界（收敛用）

| 是 | 不是 |
|----|------|
| 多支 **领域专业化** 的长期 Team | 一套流程打天下 |
| 每支队 **自定义** 三阶段工作方式 | 全局 Workflow 编辑器当核心 |
| 头脑风暴 → 定案 → 实施 的 **共性节奏** | 只要「实施」的工单调度器 |
| 团队记忆驱动的 **自主进化** | 静态配置、每次从零 |
| 可见的 **队内协作现场** | 黑盒后台跑 Agent |

## 10. 建议的 Phase 1（最小可验证）

先 **证明「一支队能按自己的方式走完三段」**，再扩多队模板。

| 步骤 | 内容 |
|------|------|
| 1 | 定义 **1 个 Team 模板**（建议应用开发队——参考多、易验证） |
| 2 | 实现 Team 持久化 + Members + 本队三阶段定义 |
| 3 | 实现 **队内现场**（append-only 时间线 + 阶段视图） |
| 4 | 接 **1 种 Harness**，能真正跑完 brainstorm → 定案 → 实施 |
| 5 | **收尾沉淀 → 团队记忆** 写回，第二次同类任务可感知差异 |
| 6 | Hub 最小 UI：选队、看阶段、看时间线 |

Phase 1 **不做**：第二、第三支队模板、复杂进化算法、全 Harness 适配、飞书/Slack 桥。

Phase 2 再扩：**短剧队、小说队** 模板，验证「同平台、异工作方式」。
